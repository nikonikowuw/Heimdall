# 统一前端抽屉组件与视觉规范

## Goal

让前端所有浮层抽屉共享实体面板材质、头部、内容滚动区和可选操作区，同时保留各业务抽屉的数据与交互差异。

## Background

- `ModalOverlay` 已统一浮层遮罩、动画、焦点陷阱、`aria-modal` 与浮层栈行为，业务抽屉通过 `variant="drawer"` 使用它。
- 7 个业务抽屉复用该外壳，但各自实现标题区、关闭按钮、内容区及可选底栏，导致结构和主题观感不一致。
- 迁移范围为账号面板、人员详情、算法版本、摄像头详情、日志详情、算法参数和算法沙箱。
- 普通表单弹窗和二次确认弹窗已使用实体材质；抽屉外观也统一为实体材质。

## Requirements

- 为业务抽屉提供统一且可组合的结构，覆盖标题区、可选工具栏、主体滚动区、可选底栏、关闭控件和尺寸变体。
- 抽屉主面板及结构化头部、工具栏、底栏使用与表单弹窗一致的实体材质和主题 token；业务内容卡片可保留其语义化背景，不要求移除所有内部层次。
- 标题区支持业务图标、说明、徽标和额外操作，不限制各 feature 的业务内容。
- 保留有实际需要的宽度差异，通过明确尺寸变体表达，不由页面拼接外壳宽度样式。
- 业务数据、请求、状态和操作仍归各 feature 管理；共享组件只负责浮层结构和呈现。
- 迁移期间保持现有遮罩、焦点、键盘关闭、层级、动画和无障碍契约。

## Acceptance Criteria

- [x] 一次性迁移全部 7 个业务抽屉，均使用共享抽屉结构和实体面板材质。
- [ ] 标题栏、关闭控件、工具栏、滚动行为和底部操作区在亮暗主题及窄视口下保持一致；业务卡片仍遵循其语义 token。（待浏览器视觉检查）
- [x] small、compact、medium、wide 尺寸变体覆盖现有抽屉宽度需求。
- [x] 各抽屉保留现有业务内容、操作行为、关闭禁用状态、退出清理、本地化文案和嵌套浮层行为。
- [x] ESC、焦点陷阱与归还、嵌套浮层优先级、背景点击关闭及减少动态效果等既有行为不回退。
- [x] 共享结构和关键交互有针对性测试；Web lint、类型检查、测试、循环依赖检查和构建通过。

## Out of Scope

- 不重构普通表单弹窗、二次确认弹窗、媒体灯箱或非浮层的内嵌属性面板。
- 不重写抽屉内的业务数据流、接口、表单字段、业务卡片或算法/摄像头操作。
