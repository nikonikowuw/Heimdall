# 感知解耦、统一规则引擎与证据三支柱落库 (Subtask 3)

## Goal

在 Rust Engine 宿主内统管硬件级预裁剪（Pre-crop ROI）、ByteTrack 航迹管理、空间几何判定（ROI/Mask/Line）与 5 秒防重复冷却，落地抓拍/告警/识别三类业务记录的数据库存储，并实现基于 `statvfs` 的“图在案在，图销案销”加权原子淘汰保护机制。

## Requirements

1. **两级分工与硬件级预裁剪 (Pre-crop ROI)**：
   - 算法包仅输出 `Vec<Detection>`，不包含任何业务规则和跟踪逻辑；
   - 若用户配置了局部特写推理区域：Engine 在显存内调用 2D 硬件（CoreVideo / RGA / VPC）裁剪出局部帧送入算法包，并将返回的目标坐标通过线性仿射变换无损还原至全景坐标系。
2. **Engine 统一航迹跟踪与几何规则引擎**：
   - 纯 Rust ByteTrack 模块持续关联目标，维护连续的 `track_id` 与移动轨迹向量；
   - 几何规则引擎判定：
     - ROI 多边形入侵（底部中心点在多边形内触发）；
     - Mask 遮罩过滤（静默丢弃区域内目标）；
     - Line 绊线越界（向量跨立求交，支持单向/双向）；
   - 统一防抖与防刷屏：同一 `track_id` 触发告警后自动进入 5 秒防重复报警冷却。
3. **业务证据中心三支柱 Schema 迁移 (SQLite WAL)**：
   - 升级数据库迁移脚本，建立 4 张核心业务表：
     - `capture_records`：行迹抓拍（全景图、特写图、目标类型、质量分、TrackID）；
     - `alarm_records`：违规告警（全景大图、特写图、规则类型、违规等级）；
     - `recognition_records`：识别对账（现场特写、底库登记照、姓名/车牌、相似度分值）；
     - `galleries`：人员/车辆底库名单（512 维 FP32 特征向量 Blob 与登记照路径）。
4. **统一存储池与原子级加权淘汰 (Atomic Eviction)**：
   - 全目录统一存储池（`var/data/evidence/`），不依赖操作系统死板物理分区；
   - 守护线程每 5 分钟调用轻量系统调用 `statvfs` 读取物理磁盘剩余空间百分比；
   - 磁盘剩余 `< 15%` 或超过配额上限时触发淘汰：**绝对优先批量淘汰普通抓拍记录（Captures）以保全告警大图**；
   - **原子级级联清理**：删除图片文件与删除 SQLite 数据库行在同一步骤内联动完成，恪守“图在案在，图销案销”，绝不留无图幽灵记录。

## Acceptance Criteria

- [ ] 算法包代码中完全不需要编写几何多边形与线段相交代码，所有规则由 Engine 统一准确判定。
- [ ] 连续经过画面的目标能稳定维持 Track ID，跨越绊线时 100% 触发告警，且 5 秒内同一目标不重复告警。
- [ ] 抓拍、告警、识别三类数据在 SQLite 中结构清晰，支持高性能带索引分页检索。
- [ ] 模拟磁盘满载时，`statvfs` 机制能稳定优先清理老旧抓拍文件及数据库行，告警记录与图片完好无损。
