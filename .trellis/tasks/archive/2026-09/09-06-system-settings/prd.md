# 系统设置模块

## Goal

为当前单管理员的 Heimdall 控制台提供一个可操作的系统设置模块，让管理员能够集中查看系统运行状态并维护平台级配置，而不需要把摄像头、算法和布防任务配置混入系统设置。

## Background and Confirmed Facts

- 当前认证模型只有一个管理员账号，没有用户、角色或权限管理模块；已有登录、初始化、当前账号和修改密码能力。
- 当前前端以左侧图标导航组织业务页面，语言、主题和修改密码入口分散在底部控制区；尚无独立的系统设置页面或导航项。
- 数据库已有 `system_configs` 表及 `SystemConfigRepo`，但当前前端没有系统设置 API。
- 仓库统一使用 `/api/v1`、JSON、`camelCase` 和固定响应信封；认证请求通过 `Authorization: Bearer <token>` 传递。
- 用户已确认本次交付为前后端一起实现，而非只做静态 UI 或 mock 页面。

## Requirements

### R1. 设置分组

系统设置包含以下五个分组：

1. 系统概览
2. 账号与安全
3. 网络/服务
4. 存储与保留策略
5. 对时服务

### R2. 单管理员模型

- 不新增用户管理、角色管理或权限矩阵。
- 已登录的当前管理员可以访问系统设置。
- 账号与安全至少覆盖当前账号信息和修改密码，并复用现有认证能力。

### R3. 可用模块

- 前端提供真实页面、分组导航、表单校验、加载/保存/失败状态和必要的危险操作确认。
- 后端提供对应的设置查询与更新接口，并持久化可编辑配置；设备网络配置必须与操作系统实际使用的配置保持一致。
- 每个设置分组独立加载和保存，避免一个请求覆盖所有配置。
- 只读运行状态与可编辑配置在界面上明确区分。

### R4. 运行时安全

- 涉及服务重启、网络连接中断、系统时间跳变或其他高风险副作用的操作必须在执行前明确提示并二次确认。
- 无法安全在线生效的参数不得伪装成即时生效；界面需标注“需重启”或对应的生效条件。
- 所有输入在 API 边界校验，错误使用项目统一错误响应。

### R5. 边缘设备网络配置

- 用户已明确：网络配置需要修改边缘设备本身的网卡 IP 地址。
- Linux 设备的网络设置提供统一操作入口；具体网络管理方式由后端检测和适配，不要求管理员先选择发行版。
- 页面读取设备实际网卡与当前 IP 配置，允许管理员修改目标网卡的 IP，并将修改实际应用到设备网络。
- 已确认生效的配置在设备重启后仍然保持；只保存表单值或数据库记录不满足要求。
- 修改当前管理网卡的 IP 时，应用前说明连接变化，提供新地址的访问指引，并明确展示应用结果或恢复状态。
- 应用后必须验证新 IP 已在内核中实际生效（`ip addr show`），不能仅凭命令退出码判断成功。

### R6. 工业级存储保留策略（对齐海康/大华 NVR）

- 存储策略对齐海康 NVR 配额模式 / 大华 Disk Quota，防止抓拍图、告警图和识别图打爆边缘设备空间。
- **四层清理架构**：
  1. 按类型配额（Quota）：每种证据类型独立配额，写满从最老删
  2. 按类型保留天数（Retention）：告警图 30 天、识别图 14 天、抓拍图 7 天
  3. 磁盘水位安全网（Watermark）：15% 触发、8% 紧急、5% 熔断
  4. 循环覆盖（Overwrite）：配额写满时覆盖最老记录，或写满停止
- 三种证据类型独立配置保留天数和配额，重要级：告警图 > 识别图 > 抓拍图
- 配置即时生效，无需重启（`StorageCleaner.config` 运行时热更新）
- 磁盘水位检测使用 `statvfs`，禁止使用 `du` 递归扫描

### R7. 对时服务

- 系统设置提供对时服务分组，展示系统时间、时区和 NTP 同步状态。
- 支持修改时区、启用/禁用 NTP、修改 NTP 服务器。
- 支持手动设置系统时间，需二次确认并记录操作日志。
- 后端封装宿主 OS 已有的 NTP 服务（timedatectl / chrony / timesyncd），不自建 NTP 客户端。
- 手动设置时间的安全约束：时间差不超过一年、NTP 启用时警告、操作日志审计。

## Acceptance Criteria

- [ ] 登录后可从全局导航进入独立的系统设置模块，并能在五个分组之间切换。
- [ ] 系统概览显示真实系统信息和运行状态；只读字段不能被误提交。
- [ ] 账号与安全可以查看当前账号并完成现有修改密码流程。
- [ ] 网络/服务、存储与保留策略、对时服务可以读取已保存配置，提交合法修改后刷新页面仍保持一致。
- [ ] 网络分组展示设备真实网卡与 IP；修改并确认生效后，目标网卡使用新 IP，设备重启后配置仍然有效。
- [ ] 修改管理网卡 IP 的流程提供新访问地址和明确的应用/恢复状态，不能把仅落库当成网络配置成功。
- [ ] 保存期间有明确的进行中状态；成功和失败结果对用户可见，失败不会丢失当前编辑内容。
- [ ] 高风险操作有明确影响说明和二次确认；需要重启或重新连接的设置正确提示生效条件。
- [ ] 前后端接口遵循 `/api/v1`、`camelCase`、统一响应信封和 Bearer 认证约定。
- [ ] 相关 Rust、前端类型检查、lint、单元测试和构建验证通过。

## Out of Scope

- 多用户、角色、权限、邀请和审计权限管理。
- 摄像头、算法、任务和规则的业务配置迁移到系统设置。
- 在没有明确运行时安全方案前，在线修改硬件并发、解码器数量等会影响管线生命周期的底层参数。
- 远程升级、备份恢复、告警通知渠道和完整运维编排，除非后续需求明确纳入。

## Open Decisions

- 各分组的具体字段、只读/可写边界和字段默认值。
- ~~配置保存后的生效策略：即时生效、下次启动生效、服务重启或重新连接。~~ **已决策**：所有存储配置即时生效，网络配置需验证内核实际生效。
- Linux 网络管理服务的适配范围、网卡归属检测、持久化与应用能力边界；这些属于后续技术调研，不以用户提供发行版名称作为规划前置条件。
- 设备网络表单的掩码/前缀长度、网关、DNS、DHCP/静态地址及 IPv4/IPv6 范围，以及应用、重新连接和失败恢复行为。
- 网络/服务与对时服务的实际运行时能力及失败回滚语义。
- API 的资源拆分、请求响应模型和错误码。
