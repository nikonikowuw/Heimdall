# 工业级网络服务配置

## Goal

为 Heimdall 边缘计算设备建立符合工业级标准（对齐海康/大华 NVR、研华工控机、华为智能网关）的网络管理子系统，彻底解决当前原型级实现中存在的**无看门狗防变砖回滚**、**无 IP 冲突检测**、**双网卡拓扑与路由冲突**、**CLI 字符串解析脆弱**以及**掉电配置损坏**等高危缺陷，保证在野外部署、工厂专网和弱电复杂环境下的绝对可用性与可靠性。

---

## Background and Confirmed Facts

- **当前实现缺陷定位**：
  - `crates/api/src/network_service.rs` 目前是 CLI（`nmcli` / `networkctl` / `ip`）字符串解析封装，未设 `LC_ALL=C`，中文系统下输出匹配直接失效。
  - 管理网卡变更缺乏回滚闭环（代码中标记 `pending_operation: None // 首版暂不实现`），一旦下发错误 IP/网关直接导致设备永久断联成砖。
  - 缺乏 RFC 5227 地址冲突检测（ACD / ARP Probe），静态 IP 冲突会导致局域网广播风暴或设备无法被访问。
  - 双网卡拓扑支持缺失，缺乏策略路由与 Metric 分级，双网口场景下极易发生默认网关冲突或非对称路由丢包。
  - 配置文件直接覆盖写入，无原子保障（`write -> fsync -> rename`），现场掉电可能导致配置文件损坏截断。
- **工业场景典型特征**：
  - 边缘设备常配备双千兆网口（LAN1 / LAN2），LAN1 专接 IPC 摄像头局域网（无网关、私网隔离），LAN2 接入上级监控/管理网络（带网关、可上外网）。
  - 设备安装在弱电机柜、室外杆顶或高空，物理拆机插串口救砖维护成本极高，任何网络失联都必须具备自动自愈能力。

---

## Requirements

### R1. 防失联事务与看门狗自动回滚（Commit-Confirm Fail-Safe）

1. **事务性网络变更**：
   - 针对管理网卡（Management Interface）的所有 IP、前缀、网关及 DNS 变更，采用 **Commit-Confirm（提交-确认）事务模型**。
   - 变更应用前，必须在系统独立运行目录生成原配置的原子恢复快照（Snapshot）。
2. **看门狗安全定时器（Watchdog Timer）**：
   - 下发变更后，系统进入「临时试运行状态（Trial/Pending）」，并立即启动一个独立线程/系统级看门狗定时器（默认 60 秒，支持 30s-300s 配置）。
   - 管理员必须通过新 IP 访问控制台并在有效时间内显式调用 `confirm` 接口确认生效。
3. **超时自动回滚（Fail-Safe Rollback）**：
   - 若在设定超时时间内未收到确认心跳，或者系统在试运行期发生异常重启，看门狗无条件将网卡配置还原为备份快照，并重启网络栈恢复连接。
   - 提供显式 `cancel` 接口允许立即手动放弃试运行并回滚。

### R2. RFC 5227 地址冲突检测（IPv4 Conflict Detection）与预检

1. **预下发 ARP 探测（ARP Probe）**：
   - 在将静态 IPv4 配置绑定到物理网卡前，必须在链路层执行 RFC 5227 标准的地址冲突检测。
   - 向目标接口广播发送 3 次 ARP Probe 报文（间隔随机化 1-2 秒），监听是否有响应。
   - 若局域网已有主机使用该 IP，立即中止应用，并向前端返回详细的冲突错误（包括冲突主机的 MAC 地址和响应时间）。
2. **免费 ARP 广播（Gratuitous ARP）**：
   - 静态 IP 成功绑定后，立即向链路层连续广播 2 次 Gratuitous ARP（ARP Announcement），强制刷新局域网二层交换机的 MAC 地址转发表和上联网关的 ARP 缓存。

### R3. 工业双网口拓扑与策略路由（Dual-NIC & Policy Routing）

1. **内外网物理隔离与分工**：
   - **LAN1（视频专网）**：默认作为摄像头私网，支持配置静态 IP / 子网掩码，**禁止或选填默认网关**；系统不为 LAN1 分配默认路由（`0.0.0.0/0`），仅维护链路直连网段路由。
   - **LAN2（业务上行网）**：接入管理网与外网，配置默认网关与外部 DNS。
2. **多网口网关互斥与 Metric 优先级**：
   - 严格防范“双默认网关冲突”。系统全局或接口层控制默认路由的跃点数（Metric），确保外部流量严格走低 Metric 的主网口。
3. **策略路由（Policy-Based Routing）防非对称丢包**：
   - 针对多网口场景配置基于源地址的策略路由规则（`ip rule add from <ip> lookup <table>`），确保从任意网口接收的请求报文，响应流严格沿该网口返回，避免工业专网跨路由非对称丢包。

### R4. 底层通信健壮性与掉电原子持久化

1. **环境变量强隔离与强类型解析**：
   - 底层调用系统工具时，必须强制注入 `LC_ALL=C` 和 `LANG=C`，杜绝系统多语言本地化导致输出匹配失效。
   - 彻底废除 `stdout.contains()` 粗糙子串匹配，全面改用 CIDR 解析库与严格的状态机比对。
   - 抽象底层驱动层：支持 NetworkManager（D-Bus/nmcli）与 systemd-networkd 双后端，未来预留轻量嵌入式 netlink 支持。
2. **掉电安全持久化（Crash-Safe Persistence）**：
   - 无论写入 `/etc/systemd/network/` 还是 NetworkManager 配置，必须遵循原子操作：`写入临时文件 -> fsync 刷盘 -> atomic rename 替换 -> 保存 .bak 镜像`，杜绝掉电损坏配置文件。

### R5. 工业级网络自检与可观测性

1. **物理层与链路层健康探测**：
   - 提供物理载波状态探测（Carrier Detect，网线是否物理插入）。
   - 协商速率与双工状态读取（Speed: 1000Mbps, Duplex: Full）。
2. **网络连通性探测工具**：
   - 提供针对网关的连通性探测（ICMP Ping / ARP Ping）。
   - 提供 DNS 解析探测能力。

## Acceptance Criteria

- [ ] **防失联回滚验证**：修改管理网卡 IP 触发试运行倒计时；若切断新 IP 连接，60 秒后网卡配置自动还原为旧 IP，原地址恢复访问。
- [ ] **确认生效闭环**：新 IP 登录后调用 confirm，操作记录被持久化，试运行状态安全解除，设备重启后新 IP 依然保持。
- [ ] **IP 冲突预检验证**：在局域网内存在同 IP 节点时设置静态 IP，系统 100% 拦截并返回冲突 MAC，网卡原网络不受干扰。
- [ ] **双网口隔离验证**：LAN1 配 192.168.1.100/24（无网关），LAN2 配 10.0.0.100/24（网关 10.0.0.1）；外网流量走 LAN2，摄像头私网流量走 LAN1，两网口 ping/http 应答均从各自接口正确返回。
- [ ] **语言普适性验证**：在 `LANG=zh_CN.UTF-8` 和 `LANG=en_US.UTF-8` 环境下，网卡列表枚举、状态和 IP 解析均正确无误。
- [ ] **掉电安全验证**：配置写入使用原子替换，并发或异常中断写入不会造成空文件或损坏的配置。
- [ ] **前端工业级交互**：管理口显示醒目标识；修改管理网卡弹出事务试运行说明；试运行期展示醒目的倒计时横幅与一键回滚/确认按钮；IP 冲突时精准标红。

---

## Out of Scope

- 802.1X 企业级端口认证（EAP-TLS 等，可后续迭代）。
- 软件网桥（Bridge）与复杂的虚拟网络命名空间编排。
- 4G/5G 蜂窝调制解调器拨号管理。
- 动态路由协议（BGP / OSPF）。
