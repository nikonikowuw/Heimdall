# 优化系统概述模块 - 工业级硬件监控仪表盘

## Goal

将系统概述模块从简单的信息展示升级为工业级边缘网关硬件监控仪表盘，提供多维度、细粒度的系统状态感知能力，支持异构 NPU 多核心监控，满足 Rockchip RK3588、华为 Ascend 等边缘 AI 平台的运维需求。

## Background

当前系统概述模块存在以下核心问题：

1. **CPU 采集粒度不足**：仅采集所有核心的平均值，无法识别热点核心和负载不均问题
2. **NPU 状态形同虚设**：`detect_npu_usage()` 直接返回 `None`，完全缺失推理硬件监控
3. **网络监控缺失**：无网络流量统计、带宽使用率、丢包错误计数
4. **温度/降频状态缺失**：无法感知热保护导致的性能骤降
5. **进程级资源占用缺失**：无法快速定位异常进程

## Requirements

### 功能需求

#### P0 - 核心指标（必须实现）

| 模块 | 指标 | 说明 |
|------|------|------|
| **CPU 多核心** | 每核心使用率 | 从 `/proc/stat` 读取每行，独立计算 |
| **CPU 多核心** | 每核心频率 | 从 `/sys/devices/system/cpu/cpu*/cpufreq/` 读取 |
| **CPU 总体** | 总体使用率 | 加权平均或汇总 |
| **CPU 总体** | 温度 | 从 thermal zone 读取 |
| **NPU 多核心** | 每核心利用率 | RKNN: `/sys/class/devfreq/*/load`<br>Ascend: ACL API |
| **NPU 多核心** | 每核心频率 | RKNN: `cur_freq`<br>Ascend: 设备信息 |
| **NPU 总体** | 内存使用 | 已用/总量/预留 |
| **内存** | 详细统计 | 总量/已用/可用/缓存/Buffer |
| **磁盘** | 详细统计 | 总量/已用/可用/Inode |

#### P1 - 网络与温度（重要）

| 模块 | 指标 | 说明 |
|------|------|------|
| **网络** | 每接口流量 | RX/TX 字节、包数、错误、丢弃 |
| **网络** | 链路状态 | 速度、双工、载波检测 |
| **温度** | 多传感器 | CPU/NPU/DDR/系统温度 |
| **温度** | 降频状态 | 是否因过热降频 |

#### P2 - 增强指标（可选）

| 模块 | 指标 | 说明 |
|------|------|------|
| **进程** | Top 5 CPU 消耗 | 快速定位异常进程 |
| **进程** | Top 5 内存消耗 | 快速定位内存泄漏 |
| **存储** | eMMC/SSD 健康度 | 写寿命、坏块（如驱动支持） |
| **NPU** | 推理会话数 | 当前并发推理任务数 |
| **NPU** | 累计推理次数 | 性能统计 |

### 非功能需求

1. **跨平台兼容**：
   - Linux (Rockchip RK3588/RK3568): 完整支持
   - Linux (华为 Ascend 310B/310P): 完整支持
   - macOS (开发机): 降级支持（无 NPU）

2. **性能开销**：
   - 默认采样间隔 2s，CPU 开销 < 0.5%
   - 高负载模式 500ms，CPU 开销 < 2%
   - 低功耗模式 10s，CPU 开销 < 0.1%

3. **权限降级**：
   - 某些指标需要 root 权限（如 devfreq 读取）
   - 无权限时提供近似值或显示 "N/A"

4. **数据新鲜度**：
   - 实时指标：2s 刷新
   - 统计指标：5s 刷新
   - 静态信息：启动时采集一次

## Acceptance Criteria

### 功能验收

- [ ] CPU 多核心监控：显示每个核心的使用率、频率，支持热力图可视化
- [ ] NPU 多核心监控：RKNN 3 核心独立显示，Ascend 设备级显示
- [ ] 网络流量监控：每接口 RX/TX 实时统计，支持曲线图
- [ ] 温度监控：多传感器温度显示，降频状态预警
- [ ] 内存详细统计：总量/已用/可用/缓存/Buffer 分项显示
- [ ] 磁盘详细统计：容量 + Inode 双维度

### 技术验收

- [ ] 后端实现 `NpuDevice` trait，支持 RKNN 和 Ascend
- [ ] 前端实现 NPU 多核心热力图组件
- [ ] API 响应时间 < 100ms（不含采样时间）
- [ ] 采样线程不阻塞 Tokio runtime
- [ ] 权限降级逻辑正常工作

### 用户体验验收

- [ ] 系统概述页面加载时间 < 1s
- [ ] 指标刷新无闪烁
- [ ] 颜色编码正确（绿/黄/红）
- [ ] 移动端响应式布局正常

## Out of Scope

- GPU 监控（除非设备有独立 GPU）
- 容器/cgroup 级别监控
- 历史数据存储和趋势分析（后续 task）
- 告警阈值配置（存储在 StorageConfig 中已有）

## Open Questions

1. **NPU 驱动版本兼容性**：不同 BSP 版本的 sysfs 路径是否一致？
2. **Ascend ACL 版本**：需要支持哪些 ACL 版本？
3. **温度传感器映射**：如何确定哪个 thermal zone 对应哪个硬件？
