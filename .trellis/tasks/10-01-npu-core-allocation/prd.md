# 宿主协同 NPU 多核分配与卡亲和架构

> 状态：planning / 修订草案，待用户评审；修订日期：2026-10-01。
> 本次仅优化任务文档，不启动实现、不创建提交。下列新行为是推荐方案，不代表已有能力或已获实施批准。

## 1. 目标与用户价值

使运维能够明确表达算法实例的算力放置意图，由宿主对真实硬件执行资源进行有界、可审计的分配；在并发启动、共享模型、配置变更、失败和停机时保持资源记录与实际生命周期一致。

交付价值：消除生产插件的进程级核心配置覆盖；支持自动打散与严格手动亲和；避免共享模型导致的虚假分核、内存倍增和资源提前回收；展示期望、分配、插件确认及硬件采样之间的区别。

不承诺每管线独占一个核，不承诺设置 mask 自动提升性能，不把宿主账本解释为跨进程硬件隔离器。

## 2. 已确认背景

完整证据及旧方案问题收敛在 `research.md`，关键事实如下：

## 3. 范围

### 本期范围

- RK3568、RK3576、RK3588 上的宿主放置契约、共享执行组、安全生命周期、插件接入及板端验证。
- 算法实例级 affinity、持久化、现有任务 API 和运行时 Apply 链路、拓扑/分配查询。
- 所有生产 RKNN session 创建入口，包括 Warmup、实时实例、共享模型、离线人脸提取、替换与自检边界。
- 保持基础 C ABI 布局不变的加法式协议协商与状态反馈。
- 现有 Web 类型/归一化/表单保存行为的兼容回归，保证不认识 affinity 的旧编辑流程不抹掉配置；不新增可视化调度页面。
- Ascend 的设备身份与内存亲和扩展边界；本期不交付跨卡执行。

### 不在本期范围

- 分布式调度、跨进程独占保证、硬实时抢占或自动热迁移。
- 根据瞬时利用率持续重绑核心、复杂加权调度或未经测量的吞吐承诺。
- 为共享人脸模型按摄像头复制权重、默认创建多 context 池、把 rknn_dup_context 当已验证的内存优化。
- Ascend 多卡搬运、跨设备零拷贝、Core ML 核级调度，以及全新 UI。
- 改变模型输入、量化、预处理、帧时间基准、业务检测结果或业务告警协议。

## 4. 需求

### R01 — 放置对象必须与硬件执行资源一致（P0）

区分业务实例与可独立放置的执行组。独立 session 的实例可各自分配；共享同一串行模型 Worker 的实例必须共享 placement，并能查询实际共享关系。多模型共享 Worker 中的必要 session 作为一个执行组核算，不据此声称只有一个 context。

同一共享组出现不兼容的手动意图时，应明确拒绝冲突，不采用先启动者静默覆盖后来者，不隐式复制模型。旧版未知能力插件只能显示未确认，不可伪造每实例分核。

### R02 — 用户配置与手动语义（P1）

配置归属算法实例；本期不增加 Task 级继承链。支持 auto / manual：auto 默认采用 spread 放置偏好；核心共享作为容量准入约束，而不是与 spread 混为同一策略枚举。

推荐变更：manual 为严格约束。缺少必需字段、设备不存在、核心越界、能力不支持或共享组冲突，返回明确错误；不取模，不偷偷换设备/核心。人工指定不意味着硬件独占。此项替代原 PRD 的越界取模方案，须在最终评审确认。

### R03 — 有界自动分配与容量保护（P0）

自动分配只在经过验证的可调度设备和核心集合内进行，选择已分配执行组较少的核心，同分时确定性轮转；已有健康组保持原放置。新成员加入共享组不重复消费执行组名额。

允许多个执行组共享核心，但受启动配置的全局/设备/核心组数、成员数、启动并发及模型驻留预算上限约束。满额快速拒绝并明确原因；不无界排队、扩线程或追加隔离资源。不把逻辑租约数当实时利用率。

### R04 — 完整生命周期与取消安全（P0）

启动预留、初始化、确认、运行、冷却、排空、退出和隔离均可追踪；所有失败路径可回收或明确保守保留资源。只有实际硬件资源已安全退出，才能释放对应 reservation。

Worker 超时/调用 future 被取消后不得释放仍在执行的资源；隔离对象继续占用额度，不靠 TTL 宣称回收成功。新旧代际互不释放；重启从持久化意图重建运行态，不恢复上一次进程的陈旧分配。

### R05 — 可验证降级而非吞错（P0）

自动请求遇到已验证的亲和设置不支持，可在有界流程中回退到 Runtime 默认调度，并明确显示 degraded / runtimeManaged；不存在“设置失败等于默认已生效”的推断。

manual 不能满足时明确失败。模型不匹配、context 无效、内存不足、设备异常等错误不得被当成可忽略的亲和警告。错误码必须绑定 Runtime/头文件/设备证据；不可把所有非零码或裸 -13 一律忽略。

### R06 — 基础 ABI 稳定与状态可信（P0）

保留 `AvAlgoAbi` 现有 64 位 96 字节布局及已有函数签名。实例配置中的宿主保留元数据不进入算法业务 schema，不受 .env/进程变量覆盖。新增协商/诊断必须是版本化、可选、加法式能力。

区分 requested、assigned、插件确认和硬件采样。插件报告绑定成功只代表 SDK 接受/插件确认，不等于测得硬件占用或模型检测语义正确。无回执只能是 unverified。

### R07 — 配置闭环与旧客户端兼容（P1）

affinity 与 algoParams 分开校验和持久化；沿用 desiredRevision / appliedRevision / applyState。省略 affinity 保留旧值；显式 null 重置 auto；新实例省略则 auto。旧 Web 保存任务不能重置手动绑定。

业务参数热更新不得改变 placement；放置变更走可控 Worker 生命周期。共享组有其他成员时，不为一个成员隐式重绑整个组；容量不足时不强行双份加载。保存期望不等于已运行，失败后保留可诊断的期望/运行态差异。

### R08 — 拓扑与诊断（P1）

复用现有 NPU 发现与监控；分别展示设备存在性、已知核心集合、可调度能力、执行组/成员/隔离占用、插件应用状态与带采样时间的硬件利用率。无设备、权限不足、未知拓扑和指标陈旧均有明确状态；不伪造一核或零负载。

诊断接口鉴权、列表有上限/分页、日志节流、指标标签低基数。不能通过业务 ResultEmitter 发系统 placement 事件，也不暴露原始指针、fd 或服务器绝对路径。

### R09 — 内存与帧亲和边界（P0）

保留现有共享模型与固定 Worker 所有权；多模型初始化预估预算包含权重、workspace、IO、预处理池及新旧代际峰值。未知内存不能记为零，也不能把单板 CMA 数值当作整个 SoC 系列固有限额。

保持原生 FrameRef 交付与既有生产设备侧路径；预留设备身份不授权跨卡读指针或自动 CPU 回退。

### R10 — 兼容迁移、发布与回滚（P1）

新宿主兼容未声明 placement 能力的老插件（auto 可运行但必须未确认；manual 不得假成功）；新插件在老宿主/本地 runner 下有明确无注入行为。完整比较宿主/插件新旧四种组合。

发布顺序、数据库加法迁移、部署开关、默认自动策略的灰度和回滚条件必须可操作。关闭 spread 不得静默取消已承诺的 manual 约束；回滚到不认识 manual 的旧版本必须先显式处理这些实例。

### R11 — 测试与性能证据（P0）

硬件无关测试覆盖配置、分配原子性、共享语义、故障注入、取消、代际、隔离、持久化与协议兼容；板端测试覆盖每个拟发布型号及实际 Runtime/BSP。

比较 Runtime 默认调度与 spread 的同负载吞吐、端到端 P50/P95、排队/丢帧、CPU、内存、fd 和热状态。不用分核日志代替真实性验证，未跑板端不得宣称已工业验收。

## 6. 评审门禁

- 本轮批准的工作只有规划文档优化；任务继续保持 planning。
- 推荐方案涉及原行为调整：执行组粒度、严格 manual、不再统一吞错，以及可选 ABI 扩展反馈。这些在 `design.md` / `api.md` 标为提案。
- 最终摘要及 API 契约须经用户确认；在后续明确批准前，不执行 task.py start，不修改产品代码。
- 板端证据暂缺不阻止完成设计；它阻止生产放置能力白名单及性能承诺，不得用开发机测试替代。
