# 宿主协同 NPU 多核分配与卡亲和架构

> 状态：planning / 修订草案，待用户评审；修订日期：2026-10-02。
> 本次获准继续优化任务文档，以工业级可验证契约为目标；不启动实现、不创建提交。除明确标注的已确认决策外，下列行为均为待评审提案，不代表已有能力或实施授权。

## 1. 目标与用户价值

用户已确认目标：每个算法实例拥有专用推理 Worker、独立检测/特征 session 与可写运行资源，由宿主独立分配 NPU 核心；同一共享域内同一模型的设备侧权重只驻留一份、跨实例复用。共享权重不等于共享串行推理 Worker。

使运维能够表达实例放置意图；在并发启动、换核、失败和停机时，执行资源与共享权重分别有界、可审计且生命周期一致。

交付价值：消除生产插件的进程级核心配置覆盖；支持自动打散与严格手动亲和；避免共享模型导致的虚假分核、内存倍增和资源提前回收；展示期望、分配、插件确认及硬件采样之间的区别。

不承诺每管线独占一个核，不承诺设置 mask 自动提升性能，不把宿主账本解释为跨进程硬件隔离器；架构层面已确立首选路线 A（控制面创建并独占移交），其底层跨线程与设核安全性待 A0 板端实测验证（见 R14）。

## 3. 范围

### 本期范围

- RK3568、RK3576、RK3588 上的宿主放置契约、实例独立执行与物理权重共享、安全生命周期、插件接入及板端验证。
- 算法实例级 affinity、持久化、现有任务 API 和运行时 Apply 链路、拓扑/分配查询。
- 所有生产 RKNN session 创建入口，包括 Warmup、实时实例、共享模型、离线人脸提取、替换与自检边界。
- 为上述契约必需的既有缺口修复：析构完成确认、Apply 版本栅栏、冷启动单实例失败隔离和可信拓扑数据来源；不扩展为无关的运行时重构。
- 保持基础 C ABI 布局不变的加法式协议协商与状态反馈。
- 现有 Web 类型/归一化/表单保存行为的兼容回归，保证不认识 affinity 的旧编辑流程不抹掉配置；不新增可视化调度页面。
- Ascend 的设备身份与内存亲和扩展边界；本期不交付跨卡执行。D1 物理共享验收针对上述 RKNN 平台，macOS 本期只保持受影响 SDK 源码兼容，不新增 Core ML 物理权重共享承诺。

### 不在本期范围

- 分布式调度、跨进程独占保证、硬实时抢占或自动热迁移。
- 根据瞬时利用率持续重绑核心、复杂加权调度或未经测量的吞吐承诺。
- 每实例复制完整权重、所有实例共用一个串行推理队列、无界 session 池、可写 workspace 跨实例复用、跨进程/跨卡/跨不兼容动态库的权重共享。独立 context 是本期必需能力，不再列为非目标。
- Ascend 多卡搬运、跨设备零拷贝、Core ML 核级调度，以及全新 UI。
- 改变模型输入、量化、预处理、帧时间基准、业务检测结果或业务告警协议。

## 4. 需求

### R01 — 一实例一执行 Worker，权重共享但执行独立（P0）

每个启用实例有自己的固定专用 Worker、独立 session 集合、有界输入队列和业务状态。宿主按实例执行组分配核心，组内包含检测/特征等必要模型 session；不以共享权重为由把多实例合并成一个可调度组。

实例 A/B/C 可以在 core 0/1/2 独立执行，同时复用相同制品的权重。不允许外层三条线程最终汇入同一个共享推理队列来冒充该架构。共享仅针对只读权重和经验证的不可变模型元信息，不共享在途可写 IO/workspace 或 tracker。

每个实例可以独立停止、失败隔离、换核；不能因共享权重而要求健康兄弟实例一起停止。设备/驱动级故障不在实例故障隔离保证内。

### R02 — 用户配置与手动语义（P1）

配置归属算法实例；本期不增加 Task 级继承链。支持 auto / manual：auto 默认采用 spread 放置偏好；核心共享作为容量准入约束，而不是与 spread 混为同一策略枚举。

已确认决策：默认自动分配，manual 为严格约束。缺少必需字段、设备不存在、核心越界、能力不支持或资源约束不满足，返回明确错误；不取模，不偷偷换设备/核心。人工指定不意味着硬件独占。用户已确认采用，替代原 PRD 的越界取模方案。

保存时对当前可信拓扑已明确无效的手动配置拒绝写入，提示合法范围；拓扑无法验证时明确报错，不猜测有效性。运行时再次校验，处理保存后的环境变化。运行中修改无法应用时保留旧健康 Worker，显示新配置失败；重启后原绑定不可满足时仅该实例启动失败，其他任务不受影响。未来核心选择界面只提供合法选项；本期不新增编辑器。

### R03 — 有界自动分配与容量保护（P0）

自动分配只在经过验证的可调度设备和核心集合内进行，选择已分配执行组较少的核心，同分时确定性轮转；已有健康组保持原放置。每个新实例必须消费独立执行组/线程/session 私有预算；已存在的同模型权重只计一次。

允许多个执行组共享核心，但受启动配置的全局/设备/核心组数、权重根/子 session 数、启动并发及模型驻留预算上限约束。满额快速拒绝并明确原因；不无界排队、扩线程或追加隔离资源。不把逻辑租约数当实时利用率。

### R04 — 完整生命周期与取消安全（P0）

启动预留、初始化、确认、运行、冷却、排空、退出和隔离均可追踪；所有失败路径可回收或明确保守保留资源。只有实际硬件资源已安全退出，才能释放对应 reservation。

Worker 超时/调用 future 被取消后不得释放仍在执行的资源；隔离对象继续占用额度，不靠 TTL 宣称回收成功。新旧代际互不释放；重启从持久化意图重建运行态，不恢复上一次进程的陈旧分配。

P0 源码缺口：`crates/infer/src/worker.rs:526-540,631-645` 在 backend 析构前通知退出，收到通知后无界 join；`worker.rs:457-471,555-572` 的初始化错误/通道断开也有同类风险。正常推理但析构阻塞时，停机仍须按配置期限进入隔离；不得把消息通道关闭或异常返回当作硬件清理成功。并发失败超过隔离熔断阈值时不得遗失任何在途 owner。

### R05 — 可验证降级而非吞错（P0）

自动请求遇到已验证的亲和设置不支持，可在有界流程中回退到 Runtime 默认调度，并明确显示 degraded / runtimeManaged；不存在“设置失败等于默认已生效”的推断。

manual 不能满足时明确失败。模型不匹配、context 无效、内存不足、设备异常等错误不得被当成可忽略的亲和警告。错误码必须绑定 Runtime/头文件/设备证据；不可把所有非零码或裸 -13 一律忽略。

### R06 — 基础 ABI 稳定与状态可信（P0）

保留 `AvAlgoAbi` 现有 64 位 96 字节布局及已有函数签名。实例配置中的宿主保留元数据不进入算法业务 schema，不受 .env/进程变量覆盖。新增协商/诊断必须是版本化、可选、加法式能力。

区分 requested、assigned、插件确认和硬件采样。插件报告绑定成功只代表 SDK 接受/插件确认，不等于测得硬件占用或模型检测语义正确。无回执只能是 unverified。

### R07 — 配置闭环与旧客户端兼容（P1）

affinity 与 algoParams 分开校验和持久化；沿用 desiredRevision / appliedRevision / applyState。省略 affinity 保留旧值；显式 null 重置 auto；新实例省略则 auto。旧 Web 保存任务不能重置手动绑定。保留现有 `UNIQUE(task_id, algorithm_id)`，不借本任务放开同任务重复算法；显式 instanceId 必须属于该任务且算法身份一致，旧客户端无 ID 时保留可验证的旧匹配语义。

P0 版本缺口：`crates/pipeline/src/coordinator.rs:440-449` 丢失真实 revision，`crates/api/src/routes/task.rs:695-705` 回写时读取最新版，`crates/db/src/repository/algorithm_instance.rs:197-265` 存在先读后写和无 revision 的失败回写。一次应用结果只能归属于启动时的目标版本；旧成功、旧失败、旧 pending 均不能覆盖新意图。停用或未运行时的配置收敛不等于硬件已绑定。

保存前拒绝必须没有配置副作用，包括同次提交的 streamMode、任务字段、实例字段和 revision。当前 `crates/api/src/routes/task.rs:343-357` 在实例校验前写入 streamMode，必须纳入事务/校验顺序回归。

业务参数热更新不得改变 placement；换核只重建本实例 session，复用原兼容权重。候选与旧实例并存须有额外私有资源预算，失败保留旧健康实例；预算不足明确拒绝，用户可显式停本实例后重启，不停兄弟实例、不复制权重。保存期望不等于已运行。模型制品升级是不同权重代际，不是换核；旧新权重都需独立计费。

### R08 — 拓扑与诊断（P1）

复用现有 NPU 发现与监控；分别展示设备存在性、已知核心集合、可调度能力、执行组/权重根/派生引用/隔离占用、插件应用状态与带采样时间的硬件利用率。无设备、权限不足、未知拓扑和指标陈旧均有明确状态；不伪造一核或零负载。

诊断接口鉴权、列表有上限/分页、日志节流、指标标签低基数。不能通过业务 ResultEmitter 发系统 placement 事件，也不暴露原始指针、fd 或服务器绝对路径。

实例配置应用与执行组资源分别可查：准入前失败没有 reservation，修改失败可以仍有旧健康 Worker；共享同一权重的实例仍有各自执行组、期望、核心和 revision；权重视图不能带一个代表所有实例的 placement/revision。设备拓扑变化与周期遥测刷新分离，负载采样失败不得伪装成设备消失或使正常初始化持续作废。

### R09 — 双层预算、只读共享与帧亲和（P0）

权重驻留与执行资源分别计费：每个同模型共享域一份权重，加上根上下文开销、每实例私有 context/workspace/IO/预处理租约、队列、离线 Worker 和替换峰值。共享物理权重不代表总内存不随实例数增长；共享 workspace 不是本任务的省内存方案。

权重从加载、所有子 session/在途调用存活直到清理完成均有 owner。一个实例销毁不能释放其他实例仍使用的权重；子 session 隔离时权重也必须保留。权重冷却保活不应保留已停实例的全部执行资源，不能把 warmup 另做成一套全模型业务实例。

未知预算不计零；老插件保守核算且不作为新架构验收结果。没有可靠预算或物理共享证明的组合不能进入本期受保障生产 profile；不把单板 CMA 数值外推为整个 SoC 系列常量。

保持原生 FrameRef 与生产设备侧路径；预留设备身份不授权跨卡读指针、CPU 像素回退或跨实例复用尚在写入的图像/张量 buffer。

### R10 — 兼容迁移、发布与回滚（P1）

基础 ABI 保持加载兼容。老插件原有 auto 行为仅作为明确的 legacy 兼容路径，不能认定满足“独立执行+共享权重”，更不能在新架构启动失败时自动切回 legacy；manual 不得假成功；新插件在老宿主/本地 runner 下有明确无注入行为。完整比较宿主/插件新旧四种组合。

发布顺序、数据库加法迁移、部署开关、默认自动策略的灰度和回滚条件必须可操作。关闭 spread 不得静默取消已承诺的 manual 约束；回滚到不认识 manual 的旧版本必须先显式处理这些实例。

### R11 — 测试与性能证据（P0）

硬件无关测试覆盖配置、分配原子性、共享语义、故障注入、取消、代际、隔离、持久化与协议兼容；板端测试覆盖每个拟发布型号及实际 Runtime/BSP。

比较 Runtime 默认调度与 spread 的同负载吞吐、端到端 P50/P95、排队/丢帧、CPU、内存、fd 和热状态。不用分核日志代替真实性验证，未跑板端不得宣称已工业验收。正确性硬门禁不能用性能收益抵销；性能负载、阈值和比较方法必须在实验前确认，不接受观察结果后移动门槛。

### R12 — 冷启动、恢复与故障隔离（P0）

同摄像头的一个算法 placement 不可满足时，其他可运行算法继续服务；跨摄像头同理。媒体输入失败与单实例算法失败分别归因，任务状态沿用现有聚合规则，聚合为 Error 不得被误用为停止健康实例的命令。没有任何可运行算法时释放本次 AI 分析资源，不关闭其他播放器/录像消费者的物理流租约。

P0 源码缺口：`crates/pipeline/src/coordinator.rs:1403-1454` 当前任一实例失败会关闭此前 Worker；`crates/api/src/routes/task.rs:972-980` 统一标错；`crates/app/src/reconcile.rs:225-313` 的恢复预处理也必须覆盖。只修增量挂载不足以满足此需求。

同模型权重首次加载须单航班，等待者取消只撤回自己的启动意图。各实例 manual 独立校验，不再把 core 0 与 core 2 求交集或判为共享组冲突。恢复采用有界、确定性的容量准入（同批 manual 先预留，再分配 auto），容量不足可以明确失败，但不能因第一份权重绑定某核心而限制所有派生 session。离线/warmup 不绕过权重与执行预算。

### R13 — 物理权重共享是硬验收，不是可选优化（P0）

同一加载算法包/Runtime 共享域、同一设备、同一模型制品及兼容初始化配置内，相同模型的设备侧权重只加载一份，多个实例派生独立执行上下文。不同模型分别共享自己的权重；检测器与特征模型不是同一份权重。

必须通过版本匹配的 SDK 共享机制、资源归属及板端内存增量共同证明；只共享 Arc、文件页缓存或模型字节不算通过。无共享能力/证据、克隆失败或预算不足明确拒绝新架构实例，不静默改为各自 rknn_init、串行共享 Worker 或 CPU 推理。RK3568 同样要求共享权重和独立执行资源，但不承诺单核设备获得核间并行加速。

受控 auto 亲和降级只允许放宽核心选择，不允许放宽独立执行与权重共享要求。跨卡、跨包动态库和新旧制品代际不承诺物理权重共享；相同包重复加载不得通过多个 registry 偷偷复制本应共享的资源。

### R14 — 线程归属与 SDK 线程安全合同（P0，待验证）

本节是 2026-10-02 复核后新增的需求，不改变 D1 架构决策，也不改变任何已确认语义。

已知事实：现行 spec（`.trellis/spec/algo-sdk/backend/algo-sdk-guidelines.md` 的 `RknnOutputsGuard` 段）已明确「同一 context 非线程安全，必须绑定所属 Worker」；官方手册仅说明 `rknn_dup_context` 面向「同模型权重复用」，未对「跨线程使用非本线程创建的 context」作出承诺。

**架构路线决策**：
- **首选主线路线 A（控制面创建后独占移交）**：架构设计与 ABI 契约默认以路线 A 作为基线推进。控制 Worker 串行完成根权重加载与 `rknn_dup_context(&root, &child)` 派生，成功后以 RAII 独占所有权胶囊（Rust 侧 `Send + !Sync`）一次性移交给目标实例 Worker。实例 Worker 在其专用线程内独占执行设核（`set_core_mask`）、独占 IO 绑定、推理与析构（`rknn_destroy`）。清理回执挂点默认归属于实例 Worker。
- **后备降级路线 B（实例线程内加锁 dup）**：作为 A0 阶段的实测后备方案。仅当 A0 板端实验证实路线 A 在目标 BSP 下存在不可逾越的 TLS 跨线程段错误或设核失效时，才触发翻转至路线 B（dup 发生在实例 Worker 内、同一 root 的并发 dup 由控制侧串行化协调）。

A0 专项实验优先验证路线 A 的 4 项判定标准（非创建线程内设核/推理/销毁、多核并发、单 child 独立销毁、根活到最后）。若路线 A 通过则正式确认采纳；若路线 A 异常则翻转路线 B；两条路线均不能满足时，该 profile 阻塞（不进入 D1 生产准入），不得通过给所有推理加全局 mutex 来掩盖线程问题，不得退回共享串行推理或每实例 `rknn_init`。

与 R05/R10/R13 的回退策略交汇点：`RequireHardware` 为**任何配置类型的下限**（含默认配置），affinity 只在此之上做核心选择，不得成为放宽理由；`runtimeManaged` 默认核心、auto 亲和降级与派生失败重试均不得放宽该策略；禁止在这些路径上出现 `debug_cpu_fallback_path` 模拟会话；注入 placement 元数据后自检硬门仍不可翻越。
