# 前端错误处理

## 错误归属

| 来源                           | 处理位置                                             |
| ------------------------------ | ---------------------------------------------------- |
| React 渲染异常                 | 根级 ErrorBoundary 兜底，高风险视频/图形视口局部隔离 |
| 未捕获 Promise / runtime error | 应用入口统一监听 `unhandledrejection` / `error`      |
| HTTP / 业务错误                | 统一 API client 解包，资源 hook 或表单呈现           |
| 媒体 / WS 断流                 | 连接状态机、退避重连与恢复操作                       |

局部异常不牵连导航和其他摄像头；故障占位提供可操作的重试，不能白屏或只静默记录。
全局异常监听不能替代局部错误处理，注册与移除必须成对。

## API client

当前入口：[lib/api.ts](../../../web/src/lib/api.ts)，`request<T>(endpoint, options: RequestInit): Promise<T>`。

- 自动附带 Bearer Token 和 `Accept-Language`；业务组件不绕过 client 直接 fetch。
- 成功校验 `code === 0` 后返回 `data`；业务错误抛 `ApiError(message, code)`，JSON 解析失败显式报错。
- 业务接口返回 401 时清除失效凭据；登录和初始化请求使用自身错误流程，避免循环登出。
- 网络错误、非 JSON、业务错误都需进入可见错误状态；不把失败伪装为空结果。
- 错误按 code 分类，优先使用服务端本地化 message，缺省文本通过 i18n。
- Toast 与表单字段错误选择一处负责，避免重复通知；当前 client 没有 `silentToast` 选项，不沿用旧草案调用。

## 连接恢复

- 业务 WS 全局复用，重连从 1000ms 开始，指数增长封顶 30000ms，增加抖动避免同步重试；连接状态由统一状态机维护。
- 媒体监听解码与连接回调；断流先给 3000ms 容错，再销毁旧实例并重建，不能叠加连接。
- 页面展示断流/重连进度与恢复操作；重连上限、取消和计时器清理必须可验证。
- 卸载、主动关闭或鉴权失效后停止重试，清理播放器、Worker、监听和 RAF。

验证 401、解析失败、网络中断、局部渲染异常、重复重连与卸载后的回调清理。
播放器细节见 [组件规范](./component-guidelines.md#播放器生命周期)。
