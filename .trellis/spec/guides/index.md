## 触发条件

### 该读架构概览

- [ ] 第一次接触这个项目
- [ ] 不确定代码该放哪个 crate
- [ ] 要新建 crate 或调整依赖关系
- [ ] 要动跨平台相关的代码

→ [架构概览](./architecture-overview.md)

### 该读边缘资源约束

- [ ] 代码会在每帧路径上执行
- [ ] 新增了队列、缓存、缓冲区
- [ ] 涉及写盘（日志、数据库、快照、录像）
- [ ] 调用了平台 SDK 或任何可能阻塞的接口
- [ ] 你正打算"先 clone 一份保平安"

→ [边缘资源约束](./edge-constraints-guide.md)

### 该想跨层问题

- [ ] 功能横跨 3 层以上（媒体、推理、管线、API、前端）
- [ ] 数据格式在层间发生转换
- [ ] 新增了事件类型、WebSocket 消息类型、配置字段
- [ ] 前端开始直接解构未定义类型的响应字段

→ [跨层思考指南](./cross-layer-thinking-guide.md)

### 该想复用问题

- [ ] 在写和已有代码相似的逻辑
- [ ] 同一个模式出现了三次以上
- [ ] 要新建工具函数 —— **先搜索**
- [ ] **要修改任何常量或配置**

→ [代码复用思考指南](./code-reuse-thinking-guide.md)

## 修改前必做

> **改任何值之前，先全局搜索它。**

```bash
rg "要改的值" .
```

Argus 里尤其重要的几类值：模型输入尺寸、类别表、时间戳单位、通道容量、API 字段名。
这些值往往同时出现在 Rust、C++、TypeScript 和 `manifest.toml` 里，改一处漏三处是常态。

## 验证 AI 交叉审查结果

AI reviewer 有固定的误报模式，收到审查意见时先核对：

- 声称"用户输入可能是恶意的" → 确认数据来源（内部 manifest？用户配置？外部 API？）
- 标记"缺少校验" → 数据是否来自可信的内部来源
- 说"行为变更" → 读代码注释，是不是有意设计
- 在测试里发现"bug" → 把被测功能想象成删掉，测试还能过吗？能过说明是同义反复测试

**核对规则**：每条 CRITICAL/WARNING 都要对照实际代码验证后再排优先级。AI 审查的误报率按 35% 预估。
