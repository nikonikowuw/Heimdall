# 跨层思考指南

> **目的**：写代码前先想清楚数据如何跨层流动。多数 bug 出在层边界，而不是层内部。

---

## 何时使用

- 变更横跨 3+ 层（FFI ↔ crate ↔ pipeline ↔ API/WS ↔ web）
- 数据格式在层间变化（帧载体、检测载荷、时间戳、坐标）
- 同一数据有多个消费者（多算法实例、多 WS 客户端、录像与 AI 并行）
- 不确定某段逻辑应落在哪层
- 新增事件类型、WS 消息、JSON 载荷或配置字段

## 步骤 1：画出数据流

`来源 → 转换 → 存储 → 消费`，对每个箭头回答：数据格式是什么？谁负责校验？失败会发生什么？

以帧路径为例：

```text
RTSP → StreamHub → 硬解 FrameRef(DMA-BUF) → 门控 → 算法包推理 → 后处理/跟踪/规则 → 事件 → SQLite/WS → 前端 Canvas
```

## 步骤 2：识别边界与契约要点

| 边界 | 契约要点 |
| --- | --- |
| crate ↔ crate | 依赖单向；跨 crate 领域类型收敛于 `types`；不泄漏 SQL DSL / 平台 SDK |
| Rust ↔ C/C++ FFI | 固定布局 C ABI、句柄创建/销毁成对、`// SAFETY:` 与双侧 `size_of`/偏移断言 |
| 宿主 ↔ 算法包 | C ABI 虚表版本、帧契约（ns 单位）、插件不共享宿主内部 track ID |
| 设备 ↔ 主机 | 拷贝点显式标注：常驻路径禁全尺寸回读；readback 仅限约定例外 |
| 后端 ↔ 前端 | `/api/v1` + camelCase + 13 位毫秒 + `[0,1]` 归一化坐标 + `T \| null` |
| WS ↔ 渲染 | 载荷由共享类型守卫收窄；渲染层不重定义 payload；高频数据不进 React state |

## 步骤 3：在边界处定义契约

对每个边界写清：输入/输出格式、单位、校验责任方、错误表达、所有权与释放时机。细节以 [全局约定](./conventions.md) 与对应专题为准，不在消费侧复制一份理解。

## 常见错误

1. **隐式格式假设**：渲染层拿到宽泛 `string` 直接当联合类型用——必须走共享收窄工具（见 [类型与时间](../web/frontend/type-safety.md)）。
2. **分散校验**：同一 payload 每个消费者各自 cast——由数据拥有者导出一个解码/守卫。
3. **泄漏抽象**：web 组件感知数据库 schema、api handler 直调硬件驱动——各层只认识邻居。
4. **双份坐标/时间语义**：源帧 PTS、展示时间与告警时间不共用同一基准——统一走 13 位毫秒与 `[0,1]` 归一化。
5. **绕过所有权约定复制帧**：跨线程转移 `FrameRef` 所有权，而不是复制像素数据。

## 检查清单

写前：

- [ ] 完整数据流已画出，每个边界的格式已写明
- [ ] 校验点唯一（入口收窄，内部复用类型）
- [ ] 队列/缓冲有上限与丢弃或降级策略

写后：

- [ ] 边界用例（null/空/非法/重连）已测
- [ ] 数据往返（写入 → 读取 → 展示）不丢信息
- [ ] 消费方复用共享解码/守卫，而不是本地 cast
