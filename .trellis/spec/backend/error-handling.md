# 错误处理

## 分层与传播

| 层           | 返回方式                                                |
| ------------ | ------------------------------------------------------- |
| 领域库 crate | `thiserror` 具体枚举，集中在 `src/error.rs`             |
| `api`        | `ApiError` + `IntoResponse`，映射 HTTP 状态和稳定业务码 |
| `app`        | `anyhow::Result` 收口，报告启动错误并退出               |

- 库公开接口不返回 `anyhow::Error`；变体带模型、摄像头、形状或操作等定位信息，保留 `source` 链。
- 错误 Display 使用中文，类型/字段用英文；避免无差别 `Other(String)`。
- 跨 crate 用 `#[from]`，仅语义不变时用 `#[error(transparent)]`。
- FFI 原码在绑定层转换；需要映射业务响应的领域错误提供 `error_code() -> u32`，不依赖 Axum。

## 降级与退出

| 故障                       | 处理                                 |
| -------------------------- | ------------------------------------ |
| 摄像头断流/超时            | 返回错误，由上层退避重连，隔离到单路 |
| 推理失败/NPU 忙            | 跳过该帧并计数；持续故障停用该实例   |
| 磁盘写失败                 | 清理或停写，保持控制面可用           |
| 启动配置/必要模型/迁移失败 | fail fast，给出可操作的错误信息      |
| 内部不变量破坏             | 可 panic，但 FFI 边界必须捕获        |

`unwrap/expect` 仅用于启动、测试或有明确证明并注释的不变量；逐帧和可恢复故障路径禁止使用。
不得因单路故障退出整个进程，也不得吞错误后伪造成功。

## API 与日志

- 领域错误到 HTTP 的转换放 API 层，不给领域类型实现 `IntoResponse`。
- 业务码与多语言消息统一见 [API 规范](./api-guidelines.md#json时间与错误) 和 [i18n](../../../crates/api/src/i18n/mod.rs)，不复制第二张映射表。
- 内部异常细节只写日志，客户端根据稳定错误码处理；消息可能随语言变化。
- 错误只在最终处理/决定降级的边界记录一次，传播层不重复打印；记录完整原因链，见 [日志](./logging-guidelines.md)。

验证每个错误分支的降级范围、HTTP 状态/业务码及敏感细节隔离。
