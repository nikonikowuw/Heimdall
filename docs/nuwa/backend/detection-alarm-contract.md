# 检测结果、告警与证据契约

## 1. 范围与状态

适用于通用检测插件 → `infer` 适配 → Pipeline 跟踪/规则 → 告警记录与证据图片。识别结果仍走 Recognitions；逐帧检测不直接生成业务告警或请求抓拍。

本页定义目标契约；以下差异尚待实现，不能将文档更新视作协议已上线：

| 边界                                                                                                   | 当前实现                                                                                                                            |
| ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| [SDK emitter](../../../crates/algo-sdk/src/emitter.rs)                                                 | 统一发射归一化对角两点式 `bbox: [x1, y1, x2, y2]`，消除 xywh 歧义                                                                 |
| [宿主解析](../../../crates/infer/src/package.rs) / [回调](../../../crates/infer/src/c_abi/loader.rs)   | 收集 JSON、提取 `objects`；严格统一按归一化对角两点式 `[x1, y1, x2, y2]` 与具名 `{x1, y1, x2, y2}` 解析构造 BoundingBox 并提供倒置防御 |
| [规则引擎](../../../crates/pipeline/src/rules.rs) / [管线](../../../crates/pipeline/src/pump.rs)       | 跟踪和规则触发后执行抓拍；未配置正向规则时支持全屏 ROI 感知兜底                                                                     |
| [AlarmDto](../../../crates/api/src/routes/alarm.rs) / [entity](../../../crates/db/src/entity/alarm.rs) | 图片字段平铺，尚无 `ruleId` / `evidenceStatus`；不能假定下述异步证据状态已落地                                                      |

## 2. 接口与兼容迁移

- SDK `emit_detections(&mut self, boxes: &[NormBox]) -> Result<(), AlgoError>` 内部统一将 `NormBox` 转换为归一化对角两点式 `[x1, y1, x2, y2]` 发射。
- 外层沿用 [AvAlgoResult](../../../crates/algo-sdk/src/c_abi.rs) 的 `kind`、`frame_id`、JSON 长度与版本头；新检测结果 `image_count=0`、`images=null`。JSON 的 `schema_version` 管理载荷契约，`api_version` 管理二进制 ABI。
- 坐标契约见 [全局约定](../guides/conventions.md#坐标)；全系统唯一格式为 `[x1, y1, x2, y2]` 归一化对角两点式，禁止 `[x, y, w, h]`。
- 宿主支持数组 `[x1, y1, x2, y2]` 与具名 `{ "x1": ..., "y1": ..., "x2": ..., "y2": ... }` 两种合法形式，自动实施坐标边界 clamp 与防倒置校准。
- 人脸识别等特定算法插件独立输出的检测目标标签为其实际检测类别（如 `"face"`），禁止随意伪装为 `"person"`，确保前后端与告警展示名副其实。
- 告警 HTTP/WS 通过现有 DTO 与共享类型映射；遵循 [API 规范](./api-guidelines.md)，保留 `/api/v1` 根信封、已有字段及类型。新字段需要同步迁移、DTO、WS 类型与消费者。

## 3. 字段与生命周期

### 检测结果

目标 JSON 使用插件内部 snake_case，必填字段如下；同一 `objects` 数组只描述外层 `frame_id` 对应的一帧：

```json
{
  "schema_version": 1,
  "objects": [
    {
      "class_id": 0,
      "label": "person",
      "confidence": 0.95,
      "bbox": [0.1, 0.2, 0.4, 0.6]
    }
  ]
}
```

- `schema_version` 为整数 `1`；`objects` 必须为数组，`[]` 表示检测成功且无目标。错误不能伪装为 `[]`，缺字段不能默认成类别 0 或零面积框。
- `class_id` 为 `u32`；`label` 为非空稳定类别键，二者的映射在算法包版本内固定。类别 ID 不跨模型通用；展示名称由 i18n 提供。
- `confidence` 为有限数且在 `[0, 1]`。`bbox` 支持数组 `[x1, y1, x2, y2]` 或具名对象；宿主自动 clamp 与防倒置校准。
- 坐标经 `unmap_box` 去 padding / 逆缩放后归一化；SDK 从 `NormBox` 转换为对角两点式再发射。
- 宿主保留 `(实例/流会话, frame_id)` 关联，补齐摄像头、算法包版本与源帧 UTC 毫秒时间。不得用回调到达时间或最新帧替代源帧；重连后的新会话不能复用旧帧关联。
- JSON 字节数、目标数量、回调缓冲与帧上下文缓存均设固定有限上限；在复制前检查字节数、解析时检查数量。具体预算在实现任务中确定并覆盖边界测试，超限不静默截断或无限扩容。

### 业务告警与证据

Pipeline 在跟踪、规则判定和冷却检查通过后生成告警；一次规则触发、一个目标、一条记录。

| 字段/数据                         | 约定                                                                                                                 |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `eventId`                         | 告警成立时生成一次 UUID；落库、重试、图片补齐和通知共用，消费方按它幂等                                              |
| `cameraId` / `ruleId` / `trackId` | 摄像头来自宿主实例；`ruleId` 必须为稳定规则标识，不能使用数组下标；跟踪 ID 在对应流会话内解释                        |
| `ruleType` / `occurredAt`         | 命中的规则类型与源帧 UTC Unix 毫秒；规则触发时间不替换成图片完成时间                                                 |
| 单目标信息                        | 保存 `targetLabel`、`confidence`、`trackId` 与具名 xyxy；现有 DTO 继续按 `bboxJson` 字符串映射，不能直接更改字段类型 |
| `status`                          | 人工处理状态，沿用 `unprocessed` / `processed`；独立于图片生成状态                                                   |
| `imageId` / `cropImageId`         | 全景图与 10% 扩边目标特写的资源关联，用于展示、核验与追溯；JSON 不内嵌图片字节                                       |
| `evidenceStatus`（待新增）        | 异步证据生成状态：`pending` → `ready` / `failed`；旧响应缺少该字段不代表已就绪                                       |

- 优先保留现有平铺的图片字段；`evidence` 只是可选组织方式，不要求增加 `evidence` / `target` 嵌套包装。当前 `imageId` / `cropImageId` 为字符串，不能直接改成 `null`；未就绪值通过兼容 DTO 映射处理。
- 告警成立后再提交有界抓拍任务，沿用 [snapshot_readback_path](./media-pipeline.md#三条路径)。全景/特写落盘且资源关联保存成功后才标记 `ready`。
- 队列满、超时或抓拍/写盘失败须结束为 `failed` 并记录原因，不能无限停在 `pending`；保留告警事实，不改人工处理状态。部分成功的图片仍受 [存储保护](./database-guidelines.md#写入与存储保护) 管理，不产生无人管理的文件。
- 图片读取沿用证据接口与路径校验。只有实际业务事件进入告警通知，不把普通检测结果逐帧推成告警。

## 4. 校验与错误矩阵

SDK 在发射前校验并返回带原因的 `AlgoError`；宿主独立校验，错误必须传回结果消费路径，不能在 C 回调中 unwind 或被空数组吞掉。

| 条件                                               | 宿主行为                                                       |
| -------------------------------------------------- | -------------------------------------------------------------- |
| 合法 v1 且 `objects: []`                           | 成功返回空检测列表，不创建告警或抓拍                           |
| ABI 头/长度与指针不匹配、未知结果类型              | 返回 `InferError::InvalidAbi`，不解引用无效载荷                |
| 非法 UTF-8/JSON、缺必填字段、未知 `schema_version` | 返回 `InferError::JsonParse`，拒绝整条结果                     |
| 类别字段非法、非有限值、置信度越界、退化/越界框    | 返回 `InferError::JsonParse`，拒绝整条结果，不静默保留部分目标 |
| JSON 或目标数量超过上限                            | 拒绝并记录超限原因，不进入跟踪/告警；检查发生在无界分配之前    |
| 帧上下文不存在、已过期或属于旧会话                 | 丢弃并计数，不绑定到当前帧或其他摄像头                         |
| 已成立告警的证据任务失败                           | 保留相同 `eventId`，证据状态为 `failed`，人工处理状态保持原值  |

## 5. 关键案例

- 旧 xywh `[0.1,0.2,0.3,0.4]` 被直接解释为 xyxy：数值合法但语义错误，适配后应为 `[0.1,0.2,0.4,0.6]`。
- 合法 v1 的 `objects: []`：正常无目标，不报协议错误、不生成告警。

## 6. 必须补齐的测试

以下是实现验收要求，不代表本次文档更新已经实现或运行这些测试：

- SDK → 宿主往返：新 `kind`、`schema_version=1`、源 `frame_id`、无 `event_id`、无图片请求；新旧协议的示例框在 f32 容差内均得到 `(0.1,0.2,0.4,0.6)`。
- 表驱动覆盖错误矩阵、合法空结果、目标/字节上限及上限加一；任何非法条目不能被默认值或 `unwrap_or_default()` 吞掉。
- 两个实例复用相同帧号、延迟回调、上下文淘汰及重连：结果只能关联原会话/源帧；回调结束后消费的元数据不依赖借用指针。
- 旧宿主/新包的能力拒绝、旧包/新宿主的显式适配、未知版本拒绝；识别与自检结果不进入检测解析器。
- 多帧命中同一规则/目标时冷却生效；同一告警的落库/通知重试沿用同一 UUID，证据补齐不创建第二条告警。
- 抓拍成功、失败、超时、队列满与部分落盘：证据状态能结束、告警事实保留、无孤儿文件；人工状态与证据状态互不覆盖。
- API/WS 往返维持现有信封、平铺字段及类型；新字段缺失时旧消费者可用，不能仅凭有告警记录就推断图片已就绪。

## 7. Wrong vs Correct

| Wrong                                  | Correct                                                         |
| -------------------------------------- | --------------------------------------------------------------- |
| 每帧检测生成业务 UUID 并自动请求抓拍   | 检测仅关联源帧；Pipeline 确认规则触发后生成告警 UUID 并请求证据 |
| 用 `status=processed` 表示图片生成成功 | `status` 表示人工处理，`evidenceStatus=ready` 表示证据生成成功  |
